# Data Generation: Auto-Labeled Hallucination Pairs

## Goal

For each Wikipedia article, generate training pairs where a named entity in the original text is replaced by whatever the LLM would hallucinate instead. The original text is labeled "correct"; the model-generated version with the swapped entity is labeled "hallucinated."

---

## Running Example

```
title:     "Marie Curie"
sentences: ["Marie Curie was born in Warsaw.", "She studied at the University of Paris."]
text:      "Marie Curie was born in Warsaw. She studied at the University of Paris."
```

---

## Step 1 — Extract Named Entities

spaCy NER finds entity spans with their character offsets:

```
entities = [("Warsaw", 24), ("University of Paris", 46)]
```

Entities at position 0 or matching the article title are skipped (trivially known to the model).

---

## Step 2 — Find `first_token` and `next_token`

For each entity, the script needs two reference token IDs.

Take entity `"Warsaw"` at offset 24. Tokenize the prefix up to the entity:

```
prefix: "...Marie Curie was born in"
```

Then re-tokenize with `@` inserted immediately after the entity in the full text:

```
"...Marie Curie was born in Warsaw @, and she studied..."
```

From this:

- **`first_token`** — the first token of "Warsaw" in the correct text (e.g., `"War"`). If the model picks this at generation step 1, it is going to produce the correct answer, so skip.
- **`next_token`** — the token immediately after `@` (e.g., `","`). This is what follows the entity in the original sentence. It serves as the termination signal during generation.

The `@` is never generated by the model — it is a tokenization trick to locate the exact token boundary after the entity.

---

## Step 3 — Generate a Hallucination

The model generates from the prefix `"...born in"` one token at a time:

1. **Check top-k at step 1**: if `first_token` (`"War"`) is in the top-4 candidates, the model would say "Warsaw" → **skip this entity**.
2. Otherwise, let the model generate freely.
3. At each subsequent step, check whether `next_token` (`","`) appears in the top-4.
4. When it does, the model has finished generating the replacement entity → **stop**.

Visually:

```
Original:    "...born in  [W][ar][saw]  [,]  and she..."
                           ↑             ↑
                       first_token   next_token

Generation:  "...born in  [B][er][lin]  [,]  and she..."
                           ↑             ↑
                   model generates     next_token appears → stop
                   freely here         (entity boundary found)
```

Everything between the prefix and `next_token` is the hallucinated entity — here, "Berlin".

---

## Step 4 — Filter and Record

The hallucinated entity is decoded and checked:

- If it overlaps with any word in the original text → discard (not a true hallucination).
- If `next_token` never appears within the window → discard (no clean splice point found).

If it passes, the record is kept:

```json
{
  "original_text": "Marie Curie was born in Warsaw. She studied at the University of Paris.",
  "title": "Marie Curie",
  "texts": ["Marie Curie was born in @Berlin@ and attended the University of Paris."],
  "new_entities": ["berlin"],
  "original_entities": [["Warsaw", 24]]
}
```

`texts`, `new_entities`, and `original_entities` are parallel arrays — one entry per successfully hallucinated entity in the article.

---

## Filter Summary

| Condition | Action |
|---|---|
| Entity at position 0 | Skip |
| Entity matches article title | Skip |
| `first_token` in model's top-k at step 1 | Skip (model would be correct) |
| `next_token` never appears within window | Skip (no clean boundary) |
| Hallucinated entity overlaps original text | Skip (not a true substitution) |

---

## Output

One file per split: `data/auto-labeled/output/{model}/data_{train,valid,test}.json`. These are consumed by `src/generate_hd.py` to extract hidden-state features for classifier training.
